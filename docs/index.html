ChaosBridge is a lightweight TCP proxy that sits between your client and a target server and injects latency, packet loss and bandwidth limits on the wire — so you can prove your systems survive the real world before your users find out the hard way.

Get started Browse the API
chaos-bridge
$ curl -X POST http://localhost:9091/proxy \
    -H "Content-Type: application/json" \
    -d '{"port":"8080","serverHost":"example.com","serverPort":"80"}'

{ "status": "success", "key": "8080:example.com:80" }

What it is

A failure switchboard for your network calls

Point your client at a ChaosBridge port instead of the real host. ChaosBridge opens a matching connection to the target and shapes every byte that flows through it. No agents, sidecars or service mesh — one small JVM process between two endpoints.

Protocol agnostic

It works on raw TCP, so HTTP, gRPC, databases and custom protocols are all fair game.

Directional control

Break the request path (upstream), the response path (downstream), or both.

Runtime REST control

Start proxies and attach or remove chaos profiles with a few JSON calls — ideal for CI.

Cheap concurrency

One virtual thread per connection means hundreds of tunnels run on minimal memory.

Get running

Quick start

ChaosBridge needs JDK 21+. Run it from source with the Gradle wrapper, or use the published Docker image.

1

Start the control plane

./gradlew run

Or pull and run the container instead:

docker run --rm -p 9091:9091 sahariardev/chaosbridge:latest

The API and web console listen on http://localhost:9091.

2

Start a proxy

Create a tunnel that forwards localhost:8080 to example.com:80. The proxy key is port:serverHost:serverPort.

curl -X POST http://localhost:9091/proxy \
  -H "Content-Type: application/json" \
  -d '{"port":"8080","serverHost":"example.com","serverPort":"80"}'
3

Inject chaos

Add 2 seconds of downstream latency to every response leaving the target.

curl -X POST "http://localhost:9091/addChaos/8080:example.com:80" \
  -H "Content-Type: application/json" \
  -d '{"chaosType":"LATENCY","line":"downstream","latency":"2"}'
4

Point your client at the proxy

Send traffic to localhost:8080 instead of the real host and watch how your retries, timeouts and circuit breakers behave.

5

Clean up

curl -X DELETE http://localhost:9091/proxy/8080:example.com:80

Reference

Chaos types

Each profile targets one direction of a proxy: upstream (client → server) or downstream (server → client).

BANDWIDTH

Bandwidth limit

Throttles a direction to bytePerSecond. Each second the pipeline forwards at most one buffer of that size, then pauses.

bytePerSecond
integer · max bytes forwarded per second
line
upstream | downstream
LATENCY

Added latency

Delays every chunk by latency seconds before it is written to the destination stream.

latency
integer · delay in seconds
line
upstream | downstream
PACKET_LOSS

Packet loss

Drops chunks with probability packetLossRate. A rate of 1.0 drops the entire direction.

packetLossRate
double · 0.0 to 1.0
line
upstream | downstream
Profiles take effect immediately

Adding or removing a profile applies on the very next chunk of data — including to connections that are already open, so keep-alive and pooled clients are affected straight away. Latency is measured in seconds, bandwidth in bytes per second, and packet loss as a probability from 0.0 to 1.0.

Observe

Metrics & dashboard

Every proxy is instrumented in memory. The console ships with a live dashboard that refreshes every few seconds, and the same data is available over JSON and Prometheus.

Per-proxy counters

Connections (total, active, failed), upstream/downstream bytes, dropped, delayed and throttled chunks, and uptime.

Host aggregation

GET /metrics rolls proxies up by target host so you can watch a single backend at a glance.

Live dashboard

The web console shows summary cards, a per-proxy table with active chaos and a detail modal for each proxy.

Prometheus ready

GET /prometheus exposes the same counters in the text exposition format for scraping.

Deploy

Docker image

The published image bundles a JDK 21 runtime and the full application. It runs as a non-root user, exposes port 9091 and logs to /app/logs.

sahariardev/chaosbridge latest

Install & run

# Pull the image
docker pull sahariardev/chaosbridge:latest

# Run the control plane
docker run --rm -p 9091:9091 sahariardev/chaosbridge:latest

The API and console are then available at http://localhost:9091.

Build from source

git clone https://github.com/sahariardev/ChaosBridge.git
cd ChaosBridge
docker build -t sahariardev/chaosbridge:latest .

Docker Compose

services:
  chaos-bridge:
    image: sahariardev/chaosbridge:latest
    ports:
      - "9091:9091"
    environment:
      MICRONAUT_SERVER_PORT: "9091"
      JAVA_OPTS: "-XX:MaxRAMPercentage=75"

Proxying to services on your host

From inside the container, reach the host with host.docker.internal when creating a proxy, for example {"serverHost":"host.docker.internal"}. On Linux, add --add-host=host.docker.internal:host-gateway.
