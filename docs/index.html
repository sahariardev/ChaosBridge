Chaos testing for resilient systems

ChaosBridge is a lightweight TCP chaos proxy built on Java Sockets and Project Loom virtual threads. Simulate latency, packet loss and bandwidth limits on the wire to prove your systems survive the real world.

Get started Browse the API
chaos-bridge
$ curl -X POST http://localhost:9091/proxy \
    -H "Content-Type: application/json" \
    -d '{"port":"8080","serverHost":"example.com","serverPort":"80"}'

{ "status": "success", "key": "8080:example.com:80" }

Why ChaosBridge

Failure injection without the ceremony

No agents, no sidecars, no service mesh. A single JVM process sits between your client and server and shapes the traffic.

⚡

Virtual threads

Every proxy and every connection stream runs on a Project Loom virtual thread, so hundreds of concurrent tunnels stay cheap.

🧪

Wire-level chaos

Latency, packet loss and bandwidth throttling are applied to the raw byte stream — independent of protocol or language.

🔌

REST controlled

Start proxies and attach chaos profiles at runtime over a small JSON API. Perfect for CI pipelines and test harnesses.

🪶

Tiny footprint

Built on Micronaut and plain sockets. No database, no message broker — just a fast embedded HTTP server and a concurrent store.

🎛️

Upstream & downstream

Target each direction independently. Break the request path, the response path, or both.

🧭

Built-in console

A Velocity + Bootstrap web UI lets you start proxies and manage chaos profiles straight from the browser.

Get running

Quick start

ChaosBridge needs JDK 21+. Clone the repository and start the server with the Gradle wrapper.

1

Build & run

./gradlew run

The API listens on http://localhost:9091 and the console is served at http://localhost:9091/.

2

Start a proxy

Create a tunnel that forwards localhost:8080 to example.com:80.

curl -X POST http://localhost:9091/proxy \
  -H "Content-Type: application/json" \
  -d '{"port":"8080","serverHost":"example.com","serverPort":"80"}'
3

Inject chaos

Add 2 seconds of downstream latency to every response.

curl -X POST "http://localhost:9091/addChaos/8080:example.com:80" \
  -H "Content-Type: application/json" \
  -d '{"chaosType":"LATENCY","line":"downstream","latency":"2"}'
4

Verify your client

Point your application at localhost:8080 instead of the real host and watch how it behaves under stress.

Core concepts

Chaos types

Each profile is applied to a single direction of a proxy: upstream (client → server) or downstream (server → client).

BANDWIDTH

Bandwidth limit

Throttles a direction to bytePerSecond. Each second the pipeline forwards at most one buffer of that size, then pauses.

bytePerSecond
integer · max bytes forwarded per second
line
upstream | downstream
LATENCY

Added latency

Delays every chunk by latency seconds before it is written to the destination stream.

latency
integer · delay in seconds
line
upstream | downstream
PACKET_LOSS

Packet loss

Drops chunks with probability packetLossRate. A rate of 1.0 drops the entire direction.

packetLossRate
double · 0.0 to 1.0
line
upstream | downstream
How it composes

A proxy pipeline is built per connection by chaining chaos handlers through piped streams, then copying the resulting stream to the socket. Profiles can be added and removed at any time and apply to the next connection.

Under the hood

Architecture

One process, three cooperating layers.

Client app
⇄
ChaosBridge proxy virtual thread per connection
⇄
Target service
  • ApiController — Micronaut REST controller that manages proxies and chaos profiles.
  • Server — accepts client sockets and forwards them to the target host over virtual threads.
  • Pipeline — assembles the configured Chaos handlers into a stream chain per direction.
  • Store — lock-free ConcurrentHashMap holding proxies and their chaos profiles.

Lifecycle of a connection

  1. Client connects to the proxy port.
  2. The proxy opens a socket to the target host and reads any configured chaos profiles.
  3. Two pipelines (upstream/downstream) chain the chaos handlers using piped streams.
  4. Bytes are copied both ways on dedicated virtual threads until one side closes.
  5. Both sockets are closed and the executor is released.

Reference

REST API

All endpoints are relative to the base URL, by default http://localhost:9091. Responses are JSON.

Proxies

GET /proxy List active proxies

Returns every proxy currently registered in the store.

{
  "data": [
    { "port": "8080", "serverHost": "example.com", "serverPort": "80", "key": "8080:example.com:80" }
  ]
}
POST /proxy Create a proxy

Starts a new listening proxy and registers it. The proxy is keyed by port:serverHost:serverPort.

FieldTypeRequiredDescription
portstringyesLocal port the proxy listens on.
serverHoststringyesTarget hostname or IP.
serverPortstringyesTarget port.
 
curl -X POST http://localhost:9091/proxy \
  -H "Content-Type: application/json" \
  -d '{"port":"8082","serverHost":"another.com","serverPort":"80"}'

# 200 OK
{ "status": "success", "key": "8082:another.com:80", "message": "Proxy started successfully ..." }
DELETE /proxy/{key} Stop a proxy

Stops the listening socket and removes the proxy and its chaos profiles from the store.

curl -X DELETE http://localhost:9091/proxy/8080:example.com:80

# 200 OK
{ "status": "success", "message": "Stopped Server 8080:example.com:80 data " }

Chaos profiles

GET /chaosConfig Describe available chaos types

Returns the public chaos types and the fields each one accepts. Internal-only types are hidden.

[
  { "type": "BANDWIDTH",   "fields": ["bytePerSecond"] },
  { "type": "LATENCY",     "fields": ["latency"] },
  { "type": "PACKET_LOSS", "fields": ["packetLossRate"] }
]
POST /addChaos/{key} Attach a chaos profile

Adds a chaos profile to the proxy identified by {key}. Accepts JSON or form-encoded bodies.

FieldTypeRequiredDescription
chaosTypestringyesBANDWIDTH, LATENCY or PACKET_LOSS.
linestringyesupstream or downstream.
bytePerSecondnumberfor BANDWIDTHMax bytes forwarded per second.
latencynumberfor LATENCYDelay in seconds.
packetLossRatenumberfor PACKET_LOSSDrop probability between 0.0 and 1.0.
 
curl -X POST http://localhost:9091/addChaos/8080:example.com:80 \
  -H "Content-Type: application/json" \
  -d '{"chaosType":"PACKET_LOSS","line":"upstream","packetLossRate":"0.3"}'

# 200 OK
{ "status": "success", "message": "Chaos Added for 8080:example.com:80 data ..." }
GET /allChaos/{key} List chaos profiles

Returns every chaos profile attached to a proxy, including the generated id used to remove it.

{
  "status": "success",
  "message": [
    { "id": "5f0c...", "type": "LATENCY", "line": "downstream", "latency": 2 }
  ]
}
DELETE /removeChaos/{key}/{chaosId} Remove a chaos profile

Removes a single chaos profile from a proxy. The profile applies to new connections immediately.

curl -X DELETE http://localhost:9091/removeChaos/8080:example.com:80/5f0c...

# 200 OK
{ "status": "success", "message": "Removed Chaos for 8080:example.com:80" }

200Successful create, list or delete.{"status":"success", ...}
